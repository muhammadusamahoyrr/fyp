# OCR evaluation fixtures — NOT in version control

Everything in this directory except this README and `.gitignore` is ignored by
git. That is deliberate and it is not a convenience.

These fixtures are real legal documents: FIRs, court orders, notices, CNICs.
Even after de-identification they are the kind of thing that must not end up in
a clone, a fork, a CI cache, or a model training set. The manifest records a
SHA-256 for each file so a run can prove it used the right bytes without those
bytes ever being committed.

## What goes here

    fixtures/
      manifest.json           <- conforms to ../ocr_evaluation_manifest.schema.json
      pages/<fixture_id>.pdf  <- the document
      transcripts/<fixture_id>.txt  <- manually verified UTF-8 ground truth

Paths inside the manifest are RELATIVE to the manifest file, and the loader
rejects absolute paths and any `..` segment.

## Before adding anything

1. De-identify it. Replace names, CNICs, phone numbers and addresses with
   consistent synthetic values *before* scanning, not after.
2. Confirm you are permitted to hold it. Record the basis in the manifest.
3. Transcribe it by hand. The transcript is the ground truth — it must never be
   generated by the OCR engine being measured, which would score the engine
   against its own output.
4. Declare handwriting honestly. Handwritten and mixed pages are
   `unsupported_by_policy` and are skipped, not scored.

## Synthetic fixtures

Allowed, for exercising harness mechanics only. Mark them `"synthetic": true`.
Any run containing one is reported as
`HARNESS_TEST_ONLY_NOT_ACCURACY_EVIDENCE` in full.
