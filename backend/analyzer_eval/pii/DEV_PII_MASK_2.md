# DEVELOPMENT measurement — `pii-mask.2` layers on pii-eval-1 (2026-10-04)

**Not a gate. pii-eval-1 is a development set. The pipeline is NOT a useful
pass.** It reaches 1 leak only by blocking 44 of 48 documents, and party
consistency is below 1.0.

## What was built (uncommitted)

- `pii_layers.py`:
  - L0: any Arabic or Urdu script in a sent sentence, masked or not, is a
    policy block. No reviewer decision lifts it.
  - L1: CNIC, phone and account numbers through OCR confusables (l/I/| → 1,
    O/o → 0).
  - L2: field labels (including "Name of the Tenant", "Tenant's CNIC") and
    pipe or tab tables.
  - Addresses: premises, "House of <Name>", street, gali, sector, block and
    phase chains.
  - L4: an alias is never merged automatically. It shares a token only
    through an explicit definition (`hereinafter called "Raza"`) or a
    reviewer's `same_person` link. Otherwise the document is blocked with
    the reason `alias_unlinked`.
  - L5: unmasked OCR-damaged names block with the reason `ocr_unmasked`.
  - L6: `leak_check` runs pattern and layout checks on the FINAL request in
    both stages (`pii_leak_guard`) and in the harness. It is independent of
    the masker, not a second pass of the same detector.
- A full name inside an address keeps its own token; a single word never
  splits an address. Token keys ignore courtesy titles only (Mr, Dr,
  sahib…), never surnames like Malik or Syed.
- Harness `pii-eval.1.1` corrections:
  - party consistency is scored only on documents actually sent;
  - blocking is reported per reason;
  - locator spans count as detections, not confirmations;
  - the manual oracle links aliases with `same_person`.

## What this shows

- **Zero leaks is reached only by blocking.** The alias rule (no automatic
  merging) blocks 39 of 48 documents, because almost every letter or
  agreement mentions a party by a short form somewhere. Party consistency
  1.0 without auto-merging means either a reviewer link for each alias, or
  a defined-alias convention in the document.
- **Even with a reviewer, party consistency is 0.71**, from:
  - OCR variants of the same name ("Hira Zaman" / "Hira Zarnan",
    "Sh0ukat");
  - locator spans that include a role word ("Between Irfan Baig",
    "Landlord Mu hammad Tahir");
  - locator mislabels ("Saeed Park Colony" as a person).
- **Remaining leaks with a reviewer (15):**
  - names neither the rules nor the locator saw, and nothing flagged
    (e.g. "Rehan Akhtar", "Kinza Arshad", "Nimra Hayat");
  - OCR-damaged "Shakeel Ahrned" (no digit, so L5 does not see it);
  - premises named after people ("Faraz Ansari Manzil", "Mushtaq Lodge",
    "house of Iqbal Hussain") inside addresses.
- **Urdu:** 11 documents blocked by policy, as required.

Raw numbers: local scratch output, regenerated by the same harness with the
saved locator output `pii-eval-1.gliner.as_loaded.json` (no new download, no
network).

## Update — narrow auto-link rule, named buildings, misspellings, role words (2026-10-04)

The owner approved a NARROW auto-link rule, with the lawyer as fallback.
Anything unresolved still stops the document's AI request. The rule
(`pii_layers.auto_link`) links a short form only when all of these hold:

- the full name is a party the document defines, with a role designation or
  role label, and nobody else holds that role;
- the short form is an exact, unique word sequence of that one full name;
- it is not a lone common surname or name element;
- it is not part of a longer capitalised name;
- its own sentence names that party's role or full name, and no other
  party's.

Fuzzy, OCR, spelling and joint-role cases never link (`name_variant`,
`alias_unlinked`).

Also added:

- buildings named after people ("X Manzil / Lodge / House"), "rear of the
  house of X", a trailing city, and words hyphenated across a line;
- locator and rule names cleaned:
  - role and function words dropped;
  - split at kinship words and ordinary lowercase words;
  - a name ending in a place word is treated as an address;
  - a name never ends mid-word ("Kash1f");
- misspelt and split names (`Ahrned`, `Moh ammad`, and a clean `Kashif` when
  only `Kash1f` was masked) now block;
- the manual reviewer links any flagged name to the same person's fullest
  other mention.

### Reading it

- **The auto-link rule changed nothing on this set.** Only 5 of the 48
  documents define a party at all; most are letters, notices and receipts.
  As approved, an alias of an undefined person goes to the lawyer.
- **Auto mode reaches 0 leaks only by blocking 46 of 48 documents. Not a
  useful pass.** With a lawyer resolving the flags, 34 of 48 are sent, with
  9 leaks.
- **The remaining leaks are names that NO layer saw**, so nothing flagged
  them, for example "Rehan Akhtar", "Nimra Hayat", "Tahir Naseem". This is
  a recall gap in detection, not a review gap.
- **Party consistency with review is 0.91.** Every remaining split is a
  party's name inside a place name ("Zaman Street", "Butt House", "Mushtaq
  Lodge"). It is masked correctly under an address token, but the metric
  counts that token as a second token for the person. The metric was not
  changed; whether it should count only NAME tokens is an owner decision for
  the pii-eval-2 rubric, before it is frozen.
- **A regression seen and fixed along the way.** Treating "bin" as a
  kinship split exposed "Bin" in "Saad Bin Tahir", and un-blocked a
  document whose missed name then leaked. Splits now happen only at
  s/o, d/o, w/o, son/daughter/wife of, and wald.

## Update — person-name party metric, missed names (2026-10-04, later)

**Metric (owner decision).** Harness `pii-eval.2` / rubric 2 scores party
consistency on PERSON-NAME REFERENCES. A party's name inside an address,
masked under the address token, is not counted as a split. The `pii-eval.1`
definition is still reported as `party_consistency_any_token`. Address
character coverage and the sent rate are reported as their own metrics.
Rubric 1 stays unchanged, because its hash is frozen for pii-eval-1.

**Harness corrections** (both are measurement fixes, not detection fixes):

- The manual reviewer now re-reviews up to three rounds. Flags that appear
  only after earlier decisions are decided too.
- Each span reports its offsets. An earlier diagnostic had misattributed
  which names leaked, by pairing spans by position.

**New general name rules:**

- `Party A/B` labels;
- Urdu legal labels: gawah (witness), mustajir/mojir (tenant/landlord),
  muddai/muddaalaih (plaintiff/defendant), wakeel (lawyer);
- "… by" headers: disclosed by, received by, signed by, and similar;
- a name right before a CNIC;
- names hyphenated across a line break ("Mah-\nnoor"):
  - kept whole;
  - one token, even across a sentence edge;
  - the same key as the unbroken form.
- A locator "address" span that contains no words is dropped; the number
  layers decide it.
